# คูปองส่วนลด — โค้ดที่ลูกค้า/แอดมินกรอกเอง

> สร้าง 2026-09-13 · โหลดเองเมื่อ Claude อ่านไฟล์ที่ตรง `paths:` ด้านบน · งานหัวข้อนี้ที่ยังไม่ได้แตะไฟล์เหล่านั้น → `Read` ไฟล์นี้เองก่อนลงมือ
> **คนละเรื่องกับโปรโมชัน** — โปรโมชันลดอัตโนมัติเมื่อเข้าเงื่อนไข (`domains/products.md`) · คูปองต้อง "กรอกโค้ด" เสมอ

## กติกาอยู่ที่ [lib/coupons.ts](../../../lib/coupons.ts) ที่เดียว (client-safe · ไม่แตะ DB)
`checkCoupon()` (ใช้ได้ไหม + เหตุผลที่ปฏิเสธ) · `computeCouponDiscount()` (ลดเท่าไหร่) · `normalizeCouponCode()` (ตัวพิมพ์ใหญ่ ไม่มีช่องว่าง — เก็บลง DB แบบนี้เสมอ) · `generateCouponCode()` (ตัดอักษรที่อ่านผิดง่าย 0/O 1/I/L 5/S 8/B ออก เพราะลูกค้าต้องอ่านโค้ดให้แอดมินฟัง)
- ⛔ **ห้ามคิดส่วนลดเอง หรือแปลเหตุผลที่ปฏิเสธเอง** ในหน้า/route อื่น — เพิ่มเคสในไฟล์นี้แทน
- เหตุผลที่ปฏิเสธต้อง **บอกให้ลงมือแก้ได้** ("ต้องซื้อครบ 1,000 บาท") ไม่ใช่ "ใช้ไม่ได้"
- ตาราง: `coupons` (กติกาใบนั้น) + `coupon_redemptions` (ใครใช้ไปแล้ว — ตัวนับ `used_count` อยู่บน `coupons`)

## ตัดสิทธิ์ตอน "สร้างบิล" เท่านั้น
| route | บทบาท |
|---|---|
| `POST /api/coupons/validate` (ต้องล็อกอิน) | **พรีวิว** ให้ฟอร์มเปิดบิล · POS · เคาน์เตอร์ — คืน `discount` + `max_discount`/`min_spend` ให้ผู้เรียกคิดต่อเองได้ |
| `POST /api/storefront/coupon` (public) | **พรีวิว** ของหน้าร้านออนไลน์ — อ่านราคาจาก DB เองเหมือน checkout (ไม่รับยอดจาก client) · กันไล่เดาโค้ดด้วย `portalRateLimit` โดย**นับเฉพาะครั้งที่โค้ดใช้ไม่ได้** (คนกรอกถูกไม่โดนล็อก) |
| route ที่สร้างบิลจริง | **ที่เดียวที่ตัดสิทธิ์** — insert `coupon_redemptions` + บวก `used_count` |
- ⛔ **ห้ามให้ route พรีวิวตัดสิทธิ์** — คนละคนกดพร้อมกันจะใช้โค้ดใบเดียวเกินโควตา
- เซิร์ฟเวอร์ **ตรวจและคิดส่วนลดใหม่เองทุกครั้ง** ตอนสร้างบิล ไม่เชื่อยอดจากหน้าจอ

## คูปอง **แทนที่** ส่วนลดท้ายบิล — ห้ามบวกกัน
`/api/pos/orders` และ `/api/storefront/checkout` เขียนยอดคูปองทับค่าที่ส่งมา แล้วส่งเข้า `computeOrderTotals()` เป็น `discountAmount` (ลงที่ `orders.discount_amount`)
- **หน้าจอต้องล็อกช่องส่วนลดมือเมื่อมีคูปอง** (POS ทำที่ `CartPanel` prop `couponDiscount`/`orderDiscountLocked`) — ปล่อยให้แก้คู่กัน = จอกับเซิร์ฟเวอร์คิดคนละยอด **แล้วแคชเชียร์รับเงินผิด**
- ฝั่งจอ **คิดส่วนลดใหม่เองเมื่อตะกร้าเปลี่ยน** ด้วย `computeCouponDiscount()` (สูตรเดียวกับเซิร์ฟเวอร์) ไม่ต้องยิง validate ซ้ำทุกครั้งที่กด +/− · ยอดต่ำกว่า `min_spend` แล้วต้องโชว์ส่วนลด 0 ทันที ไม่ใช่ค้างเลขเดิม

## ช่องทางที่ใช้ได้ (`COUPON_CHANNELS`)
`chat_order` (เปิดบิลในแชท) · `bill_online` · `storefront` · `pos` · `counter`
- ⛔ **marketplace ใช้ไม่ได้** — ยอดของ Shopee/Lazada/TikTok มาจากแพลตฟอร์ม แก้เองแล้วไม่ตรงเงินที่โอนเข้าจริง
- ⛔ **บิลตัวแทน/ฝากขาย/ส่งห้าง ใช้ไม่ได้** — มีโครงสร้างราคา (GP) ของตัวเอง
- **จอ PC (`/pc`) ยังไม่เปิดช่องกรอก** ทั้งที่ `counter` อยู่ในลิสต์ — ยอดลง `counter_sales` ไม่ได้สร้างบิล จึงตัดสิทธิ์ไม่ได้ · `PosSaleScreen` รับ prop **`couponChannel`** (ไม่ส่ง = ไม่มีช่องกรอกเลย) จะเปิดต้องออกแบบการตัดสิทธิ์ตอน confirm DSR ก่อน
- **คูปองเฉพาะคน** (`coupons.customer_id`) ใช้ที่หน้าร้านออนไลน์ไม่ได้ — ลูกค้ายังไม่มี `customer_id` ตอนกรอกโค้ด (สร้างตอน checkout) ทั้งพรีวิวและ checkout จึงส่ง `customerId: null` เหมือนกัน
- `coupons.fb_contact_id` = ออกให้ผู้ติดต่อในแชทที่ยังไม่ได้เป็นลูกค้า (ผูก `customer_id` ตอนเปิดบิลครั้งแรก) — คู่กับ `source='fb_optin'`
